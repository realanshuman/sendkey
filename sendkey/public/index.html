How it works

The key never reaches the server

This is not a promise we ask you to trust. It is how links work.

01

Encrypted on your device

Your browser creates a random 256-bit key and locks the secret with it. Only the locked version is uploaded. The key stays with you.

02

The key hides in the link

The key sits after the # in the link. Browsers never send that part of a URL to any server. It travels straight to your recipient.

03

One view, then it burns

Opening the link deletes the secret from the server in the same moment. If fifty people click at once, exactly one of them sees it.

If the database ever leaked, an attacker would find scrambled data and no keys. There is nothing useful to steal.

Security

Built so you do not have to trust us

Every claim on this page is enforced by the design, and covered by tests in the open source repo.

The server only ever sees noise

Your secret arrives already encrypted with AES-256-GCM. We store scrambled bytes and a random id. The key that opens them never comes here, so a breach of our database yields nothing worth stealing.

Burns exactly once

Reading and deleting happen as one atomic step. Two people can never both get the last view.

Expires on its own

One hour, one day, or seven days. Unopened secrets are wiped when the time runs out.

A second lock, if you want it

Add a passphrase and share it separately. It is checked on the recipient's device, so a typo cannot destroy anything.

Nothing watching you

No accounts, no cookies, no analytics, no third party scripts. The page cannot talk to anyone but us.

FAQ

Straight answers

Can you read my secret?
No. The secret is encrypted in your browser before it is uploaded, and the key never reaches us. It lives after the # in the link, which is the one part of a URL browsers never send to any server. What we store is scrambled data that we cannot open.
What if someone else opens the link first?
Then they see the secret, and your recipient sees a dead link. That sounds scary, but it means you always find out. Send the link over a channel you trust, keep the expiry short, and add a passphrase for anything serious.
What happens if nobody opens the link?
It expires on its own after the time you chose: one hour, one day, or seven days. Expired secrets are wiped from storage whether or not anyone ever opened them.
Why is the passphrase checked in my browser?
A server side check would have to either destroy the secret on a typo, or give attackers something to guess against. Checking on your device means you can retry as many times as you need, and nobody gets to guess.
Can I send files?
Not yet. SendKey is built for passwords, API keys, and short notes, up to 128 KB per secret.
What does SendKey not protect against?
Two things are worth knowing. Whoever holds the link before it is opened can read the secret, so treat the link with the same care as the secret itself. And like every tool that encrypts in the browser, it relies on the page being delivered honestly. If that matters for you, use the CLI or host it yourself.
Can I host it myself?
Yes, and for anything serious you should. It is one Go binary with no dependencies: run sendkey serve and you are live. Secrets stay in memory, or in Redis when you point it at one. It also deploys to Vercel unchanged.
